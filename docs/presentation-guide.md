# 資料の制作ガイド

## 最初に決めること

一番伝えたいこと、想定する前提知識、発表時間・利用場面、扱う範囲を決める。

## 説明の論理関係

- **What**：何が起きているか。事象や課題を、原因・解決策と区別する。
- **Why**：なぜ生じるのか、何を実現したいのか。原因と目的・要求を確認する。
- **How**：どう対処するか。原因・要求との対応、成立条件、残る制約を説明する。
- **So what**：説明した内容から何が言えるか。Howの言い換えではなく、その帰結を示す。

観測した問題の解消だけで本来の要求を満たせるかを考える。先に選んだ手段を正当化するためにWhyを設定しない。

この四つは判断の観点であり、章名・順番・ページ数は固定しない。聞き手の利益や行動目標も必須ではない。

## 用語と付録

- 必須用語は本文の初出付近で説明する。短い補足で足りなければ説明ページを設ける。
- 一般的な定義と具体例を分け、何の例かを明記する。用語と説明も太字や字下げで区別する。
- 主張の条件は、その文や図の近くに示す。本編だけで主張と理由を理解できるようにする。
- 本編の後は、Thank you → Appendix → Definition of Wordsを基本とする。Thank youとAppendixは同じ形式にし、不要な付録は省略する。

## 表現とレイアウト

- 比喩を使わず、対象・操作・関係を直接表現する。図の矢印や囲みの意味も明確にする。
- 各ページで伝えたいことを明確にする。情報が多ければ、文字を小さくする前に内容を選ぶかページを分ける。
- 本文ページの見出しサイズ・位置をそろえ、本文や図はその下に配置する。
- 説明文は日本語、技術図は英語を基本とする。図中の一般的な英語ラベルは小文字にし、固有名詞・識別子の綴りは保持する。コード・メソッド名・フィールド名は等幅にする。
- 短い説明は句点なし、定義文は句点ありを基本とする。本文・図・付録で用語の意味と表記をそろえる。

## 根拠の確認

- 一次資料を実際に開き、主張を確認する。対象バージョン・時点、提案か確定か、仕様か実装例かを区別し、出典と確認日を示す。
- 単一の実装例を全体の性質として一般化しない。事実と解釈・仮説を区別し、未確認の内容を断定しない。

## レビューと完成の判断

- 論理、用語・主張の正確さ、見た目の順に確認する。分かりづらさの原因を確認し、説明を増やすだけで対処しない。
- 修正した主張や用語は関連ページも確認する。変更ページを描画し、完成時は全ページと最終PDFを確認する。操作と確認項目は[Slidevの作業手順](slidev-workflow.md)に従う。

内容の正しさと読みやすさを確認できれば完成とし、レビューのたびに不要な要素を追加しない。
